## 3. 每日流程

排程開的 Claude 工作階段（Sonnet／low）只做三件事：跑 Python、派判讀子代理、有變更時派審查子代理。所有固定流程都在 Python。

```text
python3 scripts/patrol.py start        建立本輪紀錄 → 鎖 → 今日已完成就結束（exit 0 並印 DONE）
                                       → 前置檢查失敗：記錄 failed 原因後停止
python3 scripts/patrol.py collect      Threads／FB（新讀取器）、OPENTIX、文化部；每來源即時 record
                                       → 下載圖片、算 hash、比對貼文版本
python3 scripts/patrol.py pack         產生 patrol_state/runs/<輪>/judge_pack.json（只有新／變動內容）
   └─ Claude：Agent(model=sonnet, effort=medium) 讀 pack＋直接看圖 → 寫 proposals.json
python3 scripts/patrol.py check        Python 驗證提案；拒絕的寫明原因（可退回子代理修一次）
   └─ 有新增／修改／取消時：Agent(model=opus, effort=high) 讀原證據＋提案 → 寫 review.json
python3 scripts/patrol.py apply        依審查結果經 add_card 寫入（被質疑的改為待查）
python3 scripts/patrol.py publish      fetch＋ff → 重驗 → 逐檔提交 → push → 等同 SHA Actions → compare-public
python3 scripts/patrol.py report       報告＋收據（skip ci 提交）；需要 Eric 決定的放最上方
```

- 每步完成寫入 `state.json`；中斷後再跑 `patrol.py resume` 從下一步接續，判讀結果已存的不重送。
- 重複觸發：同一台北日期已有 `finished` → 直接結束；有活著的鎖（pid＋心跳 10 分鐘內）→ 結束並記錄「重入被擋」；鎖失效 → 記錄後接手續跑。
- `--dry-run`：做到 apply（寫到暫存 schedule 副本），不 commit、不 push。並行試跑期用 `--shadow`：只到 check，輸出提案與 agy 結果比對表。
- 網路失敗：每個來源最多 3 次重試，換路徑（重載→原帖直連→posts 子頁），每次都記錄；整輪 60 分鐘軟上限。

## 5. 提案 JSON 與 Python 驗證

判讀子代理每篇貼文都要給一筆 `disposition`，不能用總結代替。

```json
{
  "runId": "2026-10-25_0300",
  "dispositions": [
    {
      "postKey": "threads:yuzhongluo:De1UV_Ikxkl",
      "revision": "sha256:…",
      "decision": "new | update | change | cancel | already-listed | out-of-scope | not-event | needs-check",
      "reason": "一句話",
      "events": [
        {
          "action": "add | update | change | cancel",
          "targetCardId": "auto-20261024-84da22bc 或 null",
          "genre": "歌仔戲 | 布袋戲",
          "eventType": "演出 | 講座 | 體驗",
          "troupe": "羅裕誴歌劇團", "title": "府城有神・人間有情",
          "location": "新營文化中心演藝廳前「薪瀛舞台」",
          "sessions": [
            {"date": "2026-10-24", "kind": "正戲", "time": "16:30"}
          ],
          "noShowDates": [],
          "badgeType": "outdoor",
          "evidence": [
            {"field": "sessions[0].time", "source": "text", "quote": "10/24（六）16:30"},
            {"field": "location", "source": "image", "mediaSha256": "…", "region": "第3列", "reading": "薪瀛舞台"}
          ],
          "diffFromCard": [{"field": "time", "card": "未公布", "post": "16:30"}],
          "unknown": ["artist"]
        }
      ]
    }
  ]
}
```

Python 檢查（不過就拒絕或轉待查）：
1. 每篇送審貼文都有 disposition；`already-listed` 也要寫對應卡號。
2. 每個欄位都有 evidence：文字要是該貼文該版本的原文子字串；圖片要指向本輪已判讀的 `mediaSha256` 並附判讀紀錄。
3. 日期有效、在今天到 +120 天；國曆／農曆、民國年分開；介面「1 / 2」不可當日期。
4. `sessions` 每筆一個日期：**扮仙與正戲分開**；多天不同時間不可合成同一時間；`noShowDates` 內的日期不能有 session（王福宮 11/7）。
5. 同場去重：同日＋同地＋同劇團才算同場；同日同地不同劇團或不同劇目不合併。
6. **`already-listed` 時，Python 自己逐欄比對卡片**；日期、時間、地點有任何差異就不得標「一致」，自動改成 change／needs-check。
7. 社群來源一律 `verifyStatus: community`；原文沒有的欄位填「未公布」。
8. `genre` 只能是歌仔戲或布袋戲（含講座／體驗）；偶戲但沒有布袋戲／掌中戲證據 → `out-of-scope` 或 needs-check（《小狐狸買手套》）。
9. change／cancel 沿用 add_card 的同帳號限制；跨帳號的重大異動 → needs-check。

寫入時 `apply.py` 把 `sessions` 轉成網站現有欄位（`date`／`endDate`／`time`／`dateFormatted`，例如「10/23 下午3:30扮仙、10/24 下午5:00扮仙」「11/6、11/8–11/10（11/7 無演出）」），另把 `sessions` 原樣存進卡片（新增選用欄位，前端會忽略，不影響顯示，見 §11 第 4 點）。

## 6. 只送新內容給 Claude（省額度）

- 貼文版本 = 正文正規化後的 sha256＋圖片 hash 清單。同一版本判讀過就沿用結果，不再送。
- 正文或圖片變了、或規則版本升級，才重送。圖片以內容 hash 快取，換網址同一張圖不重看；看不清的不算判讀完成，下輪會再送。
- 同時把「與這些貼文可能相關的現有卡片」一起放進 pack（同劇團、同場地、或貼文提到的日期附近），讓子代理判斷是否異動。
- 每輪報告記：送出貼文數、圖片數、正文約略字數、子代理次數、重送原因。

## 9. 發布

1. fetch → 確認在 main 且能 ff-only → 在**最新** schedule 上重新跑驗證與 apply（遠端若前進過，提案會重驗）。
2. 只 `git add` 本輪檔案：`data/schedule.json`、`data/patrol_status.json`、`patrol_runs/<輪>.json`、必要時 `data/review_queue.json`。檢查 cached diff 沒有其他檔。
3. push；被拒就 fetch＋ff 後重做一次步驟 1–2，仍失敗就記 `publication=blocked` 停止。
4. 用 `gh api` 找 `head_sha == 本次 SHA` 的 Daily Opera Schedule Auto-Updater run，等到 completed（上限 20 分鐘）；SHA 不符的 run 一律不算。
5. `patrol_progress.py verify` ＋ `compare-public` 三檔一致才寫 verified；報告與收據另以 `[skip ci]` 提交。
6. 任何一步失敗：照實寫進報告最上方，不宣告完成。
