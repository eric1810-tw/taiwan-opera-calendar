# 2026-09-28 尚和／義興閣新增線索稽核

以 2026-09-28（台灣時間）為基準。`data/schedule.json` 是網站發布資料；此檔保存比對理由，不把使用者轉錄、搜尋結果或社群圖片自動等同已核實場次。

## 資料流程的責任界線

- LLM 巡檢：讀 Threads／公開 Facebook 貼文、圖片戲路表、主辦及售票頁，查重、比對異動並決定是否有足夠證據發布。只有完成核實後才編修正式 JSON。
- `updater.py`：機械性讀取文化部 API，將未核實線索寫入獨立 `data/moc_candidates.json`，並計算正式表倒數、檢查 schema、原子寫入 JSON 與最近刷新時間。其 Threads API 分支需授權，且只產生候選貼文；不能讀圖核實，也不能把候選升為已核實。公開 `data/schedule.json` 不再由機器新增候選。
- GitHub Actions：排程執行 Python 並部署網站；07:00 是排程目標，實際可能延後。LLM 的 07:00／19:00 巡檢是另一個流程；巡檢沒有確認變更時，網站不會因此新增場次。
